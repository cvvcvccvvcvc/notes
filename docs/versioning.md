# Версии и ветки

## Ветки

- `main` — единственная рабочая ветка. Обычные изменения и исправления коммитятся
  прямо в неё.

Локальные коммиты не публикуются без явного запроса. Push в `main` запускает
полную проверку и только после её успеха разворачивает commit на сервер. Force
push и удаление `main` запрещены. Ветка `dev` сейчас не используется.

## Номер версии

Production использует SemVer `MAJOR.MINOR.PATCH`. До `1.0.0`:

- `PATCH` — исправления без нового пользовательского поведения;
- `MINOR` — новые возможности и намеренные несовместимые изменения раннего
  продукта;
- `MAJOR` — начинается со стабильного публичного контракта `1.0.0`.

Версия хранится в `package.json` и `package-lock.json`. Не повышайте её после
каждого коммита: один номер описывает весь набор изменений очередного release.

## Выпуск

1. Убедиться, что все предназначенные для release изменения находятся в `main`.
2. Выбрать следующий номер по полному diff от последнего production-тега.
3. Обновить оба package-файла и сделать отдельный commit вида
   `chore: prepare vX.Y.Z release`.
4. Запустить `npm run verify`.
5. Отправить `main` в remote и дождаться обязательного `verify`.
6. Дождаться успешного workflow `Verify and deploy` и проверить production.
7. Создать на развёрнутом commit аннотированный тег `vX.Y.Z` и отправить его.

Не тегируйте неудачный deploy. Версия в package-файлах, Docker label и Git-тег
должны совпадать.

## Срочное исправление

Исправление начинается от актуального `main`, получает новый `PATCH` и проходит
обычную проверку и публикацию. Не исправляйте только сервер: такой код невозможно
воспроизвести или безопасно откатить.
